Стартовое значение близко к ln(размер словаря): в словаре игрушечного корпуса 19 символов, ln(19) ≈ 2.94. Необученная модель раздаёт символам почти равные вероятности, а небольшое превышение (3.19) объясняется тем, что случайно инициализированные логиты не точно равны. Потери падают почти до нуля, потому что корпус в ноутбуке - одна фраза, повторённая 200 раз («алгоритм внимания смотрит на все позиции сразу.»). Поэтому числа отличаются от ориентиров из условия (там символьный корпус из 62 символов и потери 4.20 → 1.76): это другой датасет, а не ошибка.

Пример генерации (температура 0.8, top_k 10, старт с символа «а»):

```
азу. алгоритм внимания смотрит на все позиции сразу. алгоритм внимания смотрит на все позиции сразу. ...
```

Модель воспроизводит фразу корпуса без искажений. До исправления багов генерация давала бессвязный набор символов.

## Найденные ошибки (шаг 2)

Подробное описание механизма каждой ошибки - в [REPORT.md](REPORT.md) и в таблице «Ваши ответы» в `dz1-bughunt.ipynb`. Кратко:

| # | Где | Механизм | Исправление |
|---|---|---|---|
| 1 | `sinusoidal_positional_encoding`: `torch.arange(1, length + 1)` | Позиции считаются с 1: первый токен получает код позиции 1, все коды сдвинуты на одну позицию относительно формулы из «Attention is All You Need». | `torch.arange(length)` |
| 2 | `LayerNorm.forward`: `mean`/`var` по `dim=0` | Статистики считаются по батчу (batch norm), а не по признакам токена. Признаки токена не нормируются, а выход примера зависит от соседей по батчу. При батче из одного примера выход обнуляется, логиты становятся равными - из-за этого падали ещё и проверки top_k и режима eval. | `dim=-1` |
| 3 | `scaled_dot_product_attention`: `softmax(dim=-2)` | Softmax по запросам, а не по ключам: строки весов не суммируются к 1, а знаменатель для ключа j суммирует по запросам i ≥ j, то есть будущее протекает в прошлые позиции в обход маски. | `dim=-1` |

Утечка будущего при ошибке 3 проверена отдельно: если исправить ошибки 1 и 2 и оставить только `softmax(dim=-2)`, падает проверка «модель не подглядывает в будущее».

## Воспроизводимость

- **Seed:** в ячейке обучения `SEED = 0` (`torch.manual_seed`, а на GPU ещё `torch.cuda.manual_seed_all`), перед генерацией seed выставляется заново. Проверки в обоих ноутбуках задают свои seed сами. Повторный запуск с нуля дал те же числа до третьего знака.
- **Устройство:** ячейка обучения сама выбирает `cuda`, если GPU доступен, иначе `cpu`, и печатает версию torch и название GPU. Проверки выполняются на CPU, как в исходном коде.
- **Окружение, на котором получены результаты:**

| | |
|---|---|
| ОС | Windows 11 Pro |
| GPU | NVIDIA GeForce RTX 3050 Laptop GPU (4 ГБ), драйвер 595.79 |
| Python | 3.14.3 |
| PyTorch | 2.12.0+cu130 (CUDA 13.0) |
| matplotlib | 3.10.8 |

На GPU одинаковые seed не всегда дают побитово те же числа, что на CPU или на другой видеокарте: потери могут отличаться в последних знаках, но характер кривой и итог (падение почти до нуля) сохраняются.

## Как повторить с нуля

### Вариант 1: Google Colab (как в условии)

1. Откройте `dz1-attention.ipynb` в Colab. Для шага 1 GPU не нужен.
2. Выполните «Среда выполнения → Выполнить все». В конце должно быть `пройдено 17 из 17`.
3. Откройте `dz1-bughunt.ipynb`, выберите «Среда выполнения → Сменить среду выполнения → T4 GPU» (необязательно, на CPU обучение тоже идёт меньше минуты).
4. «Выполнить все». Ожидается: `пройдено 17 из 17`, строка `device: cuda Tesla T4`, падение потерь примерно с 3.2 до 0.04, график потерь и фраза корпуса в генерации.

Первая ячейка каждого ноутбука ставит torch, если его нет; в Colab он уже установлен.

### Вариант 2: локально

```bash
# CPU
pip install torch matplotlib jupyter

# или GPU (NVIDIA, CUDA 13.0); подберите индекс под свою версию CUDA на pytorch.org
pip install torch --index-url https://download.pytorch.org/whl/cu130
pip install matplotlib jupyter
```

Затем выполните все ячейки обоих ноутбуков сверху вниз, в Jupyter или из командной строки:

```bash
jupyter nbconvert --to notebook --execute --inplace dz1-attention.ipynb
jupyter nbconvert --to notebook --execute --inplace dz1-bughunt.ipynb
```

Каждый ноутбук выполняется за 10-20 секунд.
